# 独立部署与参数说明

本项目是 Ubuntu 22.04 / ROS 2 Humble / C++17 的独立 colcon 工作区。原作者、移植贡献及许可证见根目录 README、NOTICE 和 LICENSE。

## 构建

先准备 ROS 2 Humble 和 rosdep，再安装工作区声明的依赖：

~~~bash
git clone https://github.com/sun-under-bird/scan-planner-stereo.git
cd scan-planner-stereo
source /opt/ros/humble/setup.bash
rosdep install --from-paths src --ignore-src -r -y
CMAKE_BUILD_PARALLEL_LEVEL=2 MAKEFLAGS=-j2 colcon build \
  --executor sequential --symlink-install \
  --cmake-args -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
source install/local_setup.bash
~~~

大型 RK3588 构建需监测可用内存、Swap 和内存压力；两任务出现压力时，在同一目录以 CMAKE_BUILD_PARALLEL_LEVEL=1 MAKEFLAGS=-j1 增量继续。原 README 列出的 Armadillo、GLEW、GLFW、OpenGL 依赖仍适用。

板端部分 ROS apt 包存放在独立依赖前缀，而非全部位于 /opt/ros/humble。本次隔离构建尝试只追加这些已安装的 ROS 依赖，未使用原 SCAN 的 install；随后按用户要求停止，本次没有完成独立构建验证。完整 ROS apt 安装可直接使用上面的标准环境；依赖位于自定义目录时，按实际目录设置 AMENT_PREFIX_PATH、CMAKE_PREFIX_PATH、LD_LIBRARY_PATH 和 Python 路径。相机 SDK、ROS deb 和原系统环境不随本仓库分发。

## 外部输入

已有系统应提供：

| 输入 | 默认话题或参考系 |
| --- | --- |
| 左右校正红外图 | /camera/camera/infra1/image_rect_raw、/camera/camera/infra2/image_rect_raw |
| 对应 CameraInfo | /camera/camera/infra1/camera_info、/camera/camera/infra2/camera_info |
| 机身里程计 | /odom |
| 规划参考系 | odom |
| 曝光时刻 TF | odom 到相机 optical frame，以及 odom 到 base_footprint |
| 实机执行速度桥 | 消费 geometry_msgs/Twist /cmd_vel |

相机驱动由外部启动。当前使用左右红外与 RGB、关闭 SDK 跨流同步、硬件深度和 IMU 的方式；软件 BM 深度由 scan_stereo_depth 生成。具体相机配置保持设备已验证版本。

base_footprint 必须是实际地面参考系，不能用 odom 的 z=0 猜地面。相机外参、机体尺寸、速度限制需按目标机器人核对，不将当前开发配置当成所有机器人的标定。

## 启动和目标点

进入本仓库并加载 ROS 与工作区环境后，仅查看深度和地图：

~~~bash
source /opt/ros/humble/setup.bash
source install/local_setup.bash
ros2 launch scan_planner passive_stereo.launch.py \
  start_controller:=false goal_topic:=/scan_preview/goal
~~~

已有底盘速度桥并需要执行轨迹时：

~~~bash
ros2 launch scan_planner passive_stereo.launch.py \
  start_controller:=true goal_topic:=/scan_preview/goal
~~~

RViz 将 2D Goal Pose 话题设置为 /scan_preview/goal，Fixed Frame 设为 odom。该入口不启动相机、Nav2、机器人 TF 或底盘桥。Nav2 与本控制器同时存在时，速度执行权由外部系统协调。深度/TF 或里程计失效时控制器停止移动。

已有软件深度发布者时使用 compute_depth:=false。其他话题参数见 src/planner/plan_manage/launch/passive_stereo.launch.py。

## 点云过滤与当前限制

配置位于 src/planner/plan_manage/config/passive_stereo.yaml：

- 高度参考 base_footprint，障碍范围 0.08～0.65 m。
- -0.10～0.08 m 的有效地面点仅提供自由射线。
- 5 cm XY 柱至少 8 个采样点，三维连通簇至少 4 个体素。
- 障碍两帧确认，保留完整三维结构。
- 一次有效自由射线且当前无障碍支持时清障；射线在障碍表面前 0.10 m 停止。
- 历史障碍 5 秒未再观测时，在新有效深度到来后退回未知并撤销膨胀。
- 全零、NaN、缺失 TF 或断流不驱动过期清障。

5 秒不是最短保留时长：有效射线可以更早清除障碍。当前策略在被动双目抖动时可能出现障碍闪烁。连续 2～3 帧自由观测再清障尚未实现。本次发布保留当前策略。固定高度裁剪不能替代坡地分割；稀疏细小障碍检出率需要实测。

调试话题 /grid_map/filtered_obstacles 是当前帧已确认障碍，不包含全部历史地图；历史占用看 /grid_map/occupancy。RViz PointCloud2 使用 Best Effort。每秒阶段统计见 /grid_map/depth_filter_statistics。

## 转向门槛

src/planner/plan_manage/config/controllers.yaml 中 heading_error_threshold 默认 0.8 rad，约 45.84°。超过时 vx/vy 置零，仅原地转向并冻结轨迹时间；回到门槛内恢复移动。

例如 60°对应 1.0472，75°对应 1.3090，90°对应 1.5708。参数只在节点启动时读取；修改配置后重启节点，运行中 ros2 param set 不会更新内部缓存。当前门槛没有滞回和平滑切换，门槛附近可能反复走停。本次发布没有修改控制参数。

## 软件验证

以下测试使用合成数据，不打开相机或向真实底盘发布速度：

~~~bash
colcon test --packages-select plan_env path_searching bspline_opt \
  --executor sequential --return-code-on-test-failure
python3 src/planner/plan_manage/test/verify_passive_stereo.py \
  --workspace "$PWD" --point-filter --goal-distance 1.0
python3 src/planner/plan_manage/test/benchmark_depth_filter.py \
  --workspace "$PWD" --seconds 10
~~~

地图过滤测试强制回环 domain 229；链路测试 domain 228，性能测试 domain 230。A* 测试也会创建 ROS 节点，执行 colcon test 前需要单独设置 domain 和回环 DDS，具体环境见验证记录。测试脚本的工作区默认路径已按自身位置解析，并支持 --workspace；链路测试全部使用指定工作区的二进制。

本次软件验证不代表实机绕障、坡地通行或长期稳定性验收。场地地图不随源码发布；可选 PCD 模式需自行提供 pcd_map_file 的有效绝对路径，默认被动双目入口不依赖 map.pcd。
